Part B adapters are written ONLY against this file. Every fact carries the vendor URL it came from. "NOT FOUND" means the vendor docs were searched and say nothing; it is never a guess. Items marked (inference) are my reading of a documented fact, labelled as such.

Policy under test: `gpu/cope-b-runpod/policy.txt` is 5015 bytes. At roughly 4 bytes per English token that is about 1,200 to 1,400 tokens (inference, not measured with any vendor tokenizer). The output instruction "Output 1 if it is toxic, 0 if it is not. Output only the single digit." is the end of line 1 of the file (the opening sentence plus that instruction); the file itself ends with the "Decisive defaults" paragraph (checked locally against `gpu/cope-b-runpod/policy.txt`). An adapter must therefore strip or rewrite that sentence near the START of the policy and map it onto typed options (see Cross-provider notes).

## 1. TypeSafe Jev

Product resolves: yes. "Jev" is TypeSafe's flagship System One decision model. Current model `jev-1.13.0`; aliases `jev-latest` and `jev-preview` both point to it today. Source: https://docs.typesafe.ai/models.md

1. **Endpoint and auth.** `POST https://api.typesafe.ai/v1/systemone`, header `Authorization: Bearer <API_KEY>`, `Content-Type: application/json`. Source: https://docs.typesafe.ai/api.md. Model list: `GET https://api.typesafe.ai/v1/models` (https://docs.typesafe.ai/models.md).
2. **Request body.** Top-level fields `state` (string, object or array; required), `model` (string; required), `questions` (map of your own question id to a question object; required). Source: https://docs.typesafe.ai/api.md
   - noul: `{"type":"noul","instructions":<string|object|array>,"criteria":{"true":..,"false":..}}`; `criteria` optional.
   - choice: `{"type":"choice","instructions":<string|object|array>,"criteria":{"<option>":<string|object|array|null>,...}}`; `criteria` required; at most 255 options.
   - score: `{"type":"score","instructions":..,"criteria":[<level>,...]}`; 2 to 10 levels.
   - Question ids are not sent to the model (https://docs.typesafe.ai/primitives/choice.md). Option names and descriptions are sent.
3. **Free-text instruction.** YES. `instructions` is a free string and may also be an object holding the question plus referenced data (https://docs.typesafe.ai/api.md). No `instructions` length cap is documented. The only documented budget is context: "64k tokens per request; 32k tokens for `state` plus the longest question" (https://docs.typesafe.ai/models.md). The 5015-byte policy (about 1.3k tokens, inference) fits. Use a `choice` question with two options so the answer is normalised (item 4). Whether the model follows a policy of this length well is unverified (the vendor lists accuracy "jaggedness": https://docs.typesafe.ai/model-jaggedness/jev-1.13.md, not read in full).
4. **Response shape.** Source: https://docs.typesafe.ai/api.md
   ```json
   {"model":"jev-1.13.0","answers":{"<id>":{"type":"choice","choice":"billing","probabilities":{"billing":0.88,"technical":0.12,"sales":0.0},"confidence":0.81}},"usage":{"input_tokens":318,"output_tokens":34}}
   ```
   - choice: `choice` = highest-probability option; `probabilities` = "floats that sum to 1" over the options you supplied, so it IS normalised over the answer set; `confidence` in 0..1 derived from the distribution.
   - noul: `{"type":"noul","noul":0.95}`, "the probability the answer is yes". The docs do not say it is normalised against an explicit "no" answer set; there is no `probabilities` map.
   - Response header `x-typesafe-request-id` (https://docs.typesafe.ai/sdk/python/api/types/responses.md).
5. **Batching.** Documented batching is many questions per ONE state: "Jev ingests the `state` once and evaluates every question against it in parallel" (https://docs.typesafe.ai/models.md). No maximum question count was found (NOT FOUND in https://docs.typesafe.ai/api.md and https://docs.typesafe.ai/models.md). A request holds one `state`; there is no "list of independent items" field. `state` may be an array of text values (https://docs.typesafe.ai/models.md), and the docs say a question can point at nested `state` values by name in backticks (https://docs.typesafe.ai/api.md, `instructions` section). So the policy-once design (policy plus all posts in `state`, one question per post) is plausible but is NOT shown in any documented example and its accuracy is unverified. The safe design is one post per request with the policy in `instructions`.
6. **Billing and usage.**
   - Per request: `usage.input_tokens` and `usage.output_tokens` are returned (https://docs.typesafe.ai/api.md). Billing is "Charged per input token. Output tokens are free." (https://docs.typesafe.ai/models.md). So real spend = sum of `input_tokens` x price.
   - Spend bound: the primary bound is OUR client-side meter: sum `usage.input_tokens` from completed responses and add a pre-request token estimate for in-flight calls, stopping at the run cap. Credits are only a backstop (inference): MCA 8.2(a)(ii)(z) opens with "Unless otherwise set forth in the Order" and says that if the customer has not opted in to automatic refills, "TypeSafe may decline to generate Output in response to Customer's submission of Input". That is permissive ("may"), not a guaranteed stop, and 8.1 separately describes invoiced Fees (https://typesafe.ai/legal/mca, sections 8.1 and 8.2(a), re-read 2026-10-09). Do not rely on prepaid credits to halt spend.
   - Cancellation: NOT FOUND (searched https://docs.typesafe.ai/api.md, https://docs.typesafe.ai/models.md, https://docs.typesafe.ai/sdk/python/api/exceptions.md listing, https://typesafe.ai/legal/mca). The API is a single synchronous POST with no job id.
   - Billing of cancelled or timed-out requests: NOT FOUND. Treat as billable and bound spend by the credit balance plus a client-side token estimate.
7. **Price.** `jev-1.13.0`: "$42 / $0.042" per billion / per million input tokens; output free. Read 2026-10-09. Source: https://docs.typesafe.ai/models.md
8. **Rate limits.** "100K tokens per second / 80 requests per second"; over either limit returns `429`; `529 Overloaded` is also possible. The page warns limits "can change without notice". The SDKs honour `retry-after` when present. Sources: https://docs.typesafe.ai/models.md and https://docs.typesafe.ai/api.md (Errors: 401, 422, 429, 529).
9. **Data retention / training.** Models page: "Jev is not trained on customer requests or responses" (https://docs.typesafe.ai/models.md). Zero data retention (ZDR) is offered to enterprise customers only (https://docs.typesafe.ai/legal.md). The DPA says Customer Personal Data is "retained for as long as necessary taking into account the purpose of the Processing" (https://typesafe.ai/legal/data-processing, section 8 "Duration of Processing"); no fixed retention period is given. MCA section 4.1: TypeSafe "will not, include Customer Data in a dataset used to train ... any artificial intelligence or machine learning models without Customer's prior consent" (https://typesafe.ai/legal/mca). **Restriction on us:** MCA section 2.3(b) forbids using "the Services or any Output ... to perform model distillation, train a model to imitate the output of the Services, or develop ... a similar or competing product". Using Jev labels as training data for Charcoal's classifier would need legal review; pure evaluation scoring is not obviously covered but is not explicitly permitted either.
10. **Identity.** YES. Response `model` carries the versioned id (`jev-1.13.0`) even when the request used an alias: "The response's `model` field reports the versioned ID that answered" (https://docs.typesafe.ai/models.md). Pin by sending `jev-1.13.0` instead of `jev-latest`.

## 2. Cloudflare Workers AI: Clef-flash (9B) and Clef (27B)

Products resolve: yes. `@cf/cloudflare/clef-flash` (9B) and `@cf/cloudflare/clef` (27B), launched 2026-10-01; `@cf/cloudflare/clef-omni` was added 2026-10-09 and is out of scope. Sources: https://developers.cloudflare.com/workers-ai/models/clef-flash/ , https://developers.cloudflare.com/workers-ai/models/clef/ , https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/ , https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/. Open weights (Apache 2.0): https://huggingface.co/Cloudflare/clef-flash , https://huggingface.co/Cloudflare/clef.

Vendor changelog history (not a conflict, the hosted model changed): the 2026-10-01 launch changelog listed Clef-flash with a 64K-token context (https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/). The 2026-10-09 changelog says "Clef-flash now costs $0.038 per million input tokens, down from $0.090 ... To offer this price, the hosted Clef-flash context window is now 24K tokens, down from 64K", that Clef "keeps its 64K context window", and that the Clef-flash Hugging Face weights "are unchanged and support up to a 256K context window if you self-host" (https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/). The current values used below ($0.038/M, 24,576 tokens on the model page) are the post-2026-10-09 ones. Cloudflare changed the hosted model's limits and price within nine days, so pin by logging the run date.

1. **Endpoint and auth.** `POST https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/run/@cf/cloudflare/clef-flash` (or `.../clef`), header `Authorization: Bearer <CLOUDFLARE_AUTH_TOKEN>`. Also available through the Workers binding `env.AI.run(...)` and AI Gateway. Source: https://developers.cloudflare.com/workers-ai/models/clef-flash/index.md and https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/
2. **Request body.** Source: https://developers.cloudflare.com/workers-ai/models/clef-flash/schema-input.json . Required: `model` (string, must match `^\s*(clef|clef-flash)\s*$`; "clef-flash" or "clef" selects the model), `state` (string, object or array), `questions` (map id to question; 1 to 64 questions; ids use letters, digits, `_`, `.`, `-`, max 100 chars). Optional `images` (max 4; not used here). Question shapes are the same System One shapes as Jev:
   - noul: `{"type":"noul","instructions":<non-empty string|object|array>,"criteria":{"true":..,"false":..}}`
   - choice: `{"type":"choice","instructions":..,"criteria":{"<option id>": <string|object|array|null>}}`, 2 to 255 options, `criteria` required.
   - score: `criteria` an ordered array of 2 to 10 levels.
   Note the body repeats the model name in `model` in addition to the URL path.
3. **Free-text instruction.** YES. `instructions` is "a non-empty string, or an object/array" with NO `maxLength` in the input schema (https://developers.cloudflare.com/workers-ai/models/clef-flash/schema-input.json). The limit is the context window: Clef-flash 24,576 tokens, Clef 65,536 tokens. "Media tokens count toward the model's context window, together with the questions. ... the text `state` is truncated to fit the remaining space." (https://developers.cloudflare.com/workers-ai/models/clef-flash/). The 5015-byte policy (about 1.3k tokens, inference) fits both. The hosted Clef-flash window was cut from 64K to 24K tokens on 2026-10-09 (https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/), which shows Cloudflare can change hosted limits without a model-id change. IMPORTANT: if `state` is too long it is silently truncated, not rejected; the adapter must keep post plus policy well under the window.
4. **Response shape.** Source: https://developers.cloudflare.com/workers-ai/models/clef-flash/schema-output.json
   ```json
   {"model":"...","answers":{"<id>":{"type":"choice","choice":"<top option>","probabilities":{"<opt>":0.0},"confidence":0.0}},"usage":{"input_tokens":0,"output_tokens":0}}
   ```
   - choice: `probabilities` "values sum to 1" over the supplied options (normalised over the answer set); `choice` is the highest-probability option.
   - noul: `{"type":"noul","noul":<0..1>}`, "Probability the answer is yes." No `probabilities` map; normalisation against an explicit no set is not stated.
   - score: `score`, `legend`, `probabilities`, `confidence`.
   The REST call is the Workers AI `/ai/run` endpoint; the schema above is the model output. The Cloudflare REST envelope wrapper (`result`, `success`, `errors`) is not shown on the model page (NOT FOUND there); the adapter must confirm it against a real response in the first live test.
5. **Batching.** Same as Jev: up to 64 questions against one `state` per request (schema-input.json `maxProperties: 64`). The "state" may be an array/object. The documented prefix sharing says "a request ... one state"; there is no multi-item request field. The policy-once design (policy and posts in `state`, a question per post) is possible within the 64-question cap but is not shown in any vendor example and is unverified for accuracy. Safe design: one post per request, policy in `instructions`.
6. **Billing and usage.**
   - Per request: `usage.input_tokens` and `usage.output_tokens` are required response fields (schema-output.json). "Clef models do not charge for output tokens." (https://developers.cloudflare.com/workers-ai/models/clef-flash/). Real spend = `input_tokens` x price.
   - Limits and their softness: (a) free allocation 10,000 Neurons/day, beyond which Workers Paid bills at $0.011 per 1,000 Neurons; "If you exceed any one of the above limits, further operations will fail with an error" (https://developers.cloudflare.com/workers-ai/platform/pricing/). Workers Paid has no documented hard cap there. (b) AI Gateway spend limits: spend limits are labelled **Beta** in the docs navigation. Dollar budgets per gateway block with `429` once reached, but "Spend limits are eventually consistent. The current request's cost is recorded after completion, so a burst of concurrent requests can briefly exceed the limit", and "Cost tracking is a best-effort estimation based on token counts and model pricing. Refer to your provider's dashboard for exact billing amounts." (https://developers.cloudflare.com/ai-gateway/features/spend-limits/, re-read 2026-10-09). (c) Prepaid Unified Billing credits "deduct from your AI Gateway credit balance in real time" (https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/); what happens at a zero balance: NOT FOUND on that page. (d) The same manage-gateway page documents a gateway "Retry requests" setting that can "automatically retry failed requests to upstream providers"; it must stay OFF for the eval or retried calls make the client-side meter under-count. The Clef page says AI Gateway works with these endpoints (https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/). Recommended bound for Part B: the primary bound is a client-side meter of `usage.input_tokens` (plus a pre-request estimate for in-flight calls); a gateway spend limit (Beta) is a secondary backstop only.
   - Cancellation: NOT FOUND (searched the two model pages, pricing, limits, and a Cloudflare docs search for "failed requests errors timeouts charged"). Requests are synchronous.
   - Billing of cancelled or timed-out requests: NOT FOUND.
7. **Price.** Clef-flash: $0.038 per M input tokens (3,455 neurons per M); Clef: $0.24 per M input tokens (21,818 neurons per M); no output charge. Read 2026-10-09 ("Last updated Oct 9, 2026"). The 2026-10-09 changelog says Clef-flash price was cut from $0.090 to $0.038 per million input tokens. Sources: https://developers.cloudflare.com/workers-ai/platform/pricing/ , https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/
8. **Rate limits.** The limits page lists "Text Generation: 300 requests per minute, unless the model requires the Workers Paid plan" (https://developers.cloudflare.com/workers-ai/platform/limits/, last updated Sep 17, 2026). The Clef model pages are labelled "Text Generation" and do not state a paid-plan requirement, so 300 requests/minute is the likely limit (inference). No Clef-specific limit or tokens-per-minute limit was found. Paid-model limits (20 to 50 requests/minute) apply only to listed frontier models, and Clef is not in that list.
9. **Data retention / training.** "Cloudflare does not use your Customer Content to (1) train any AI models made available on Workers AI or (2) improve any Cloudflare or third-party services, and would not do so unless we received your explicit consent." Customer Content "may be stored by Cloudflare if you specifically use a storage service". No retention period for inference inputs is stated. Source: https://developers.cloudflare.com/workers-ai/platform/data-usage/ (last updated Apr 21, 2026). If AI Gateway is used, its request logging is a separate setting (not reviewed here).
10. **Identity.** Partly. The response has `model` described as "The model that performed the evaluation" (schema-output.json). Whether it returns a pinned version or just `clef-flash` was not shown in any example (NOT FOUND). The model id `@cf/cloudflare/clef-flash` carries no version; weights are on Hugging Face (https://huggingface.co/Cloudflare/clef-flash). Cloudflare can change the hosted model silently: the 2026-10-09 changelog cut the Clef-flash context window from 64K to 24K tokens and its price from $0.090 to $0.038 per million input tokens under the same model id (https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/). Log the response `model` plus the run date.

## 3. AWS Strands Decider 2B (local server)

Product resolves: yes. Open source under Apache-2.0 at https://github.com/strands-labs/strands-decider . Reference weights `StrandsAgents/strands-decider-2B-qwen3.5-v1-2610` (1.9B parameters, Qwen3.5-2B-Base plus LoRA and a pointer head). Earlier checkpoints `strands-decider-2B-hobson-v21` and `-v19` remain published. Sources: https://raw.githubusercontent.com/strands-labs/strands-decider/main/README.md , https://huggingface.co/StrandsAgents/strands-decider-2B-hobson-v19 . README says the five v1 models are also under the `amazon` Hugging Face org.

1. **Endpoint and auth.** `POST http://127.0.0.1:<port>/v1/systemone`; `GET /health` returns "the model name, the checkpoint path, the base model, the device and the calibration temperature". Start with `pip install strands-decider` then `strands-decider serve StrandsAgents/strands-decider-2B-qwen3.5-v1-2610 --port 8000 [--device cuda|mps|cpu|mlx]`. NO authentication; binds to 127.0.0.1 by default. Sources: README above and https://raw.githubusercontent.com/strands-labs/strands-decider/main/docs/inference.md (section Serve). The extras for devices (`cuda`, `mps`, `cpu`, `mlx`) are noted as shipping with the next release; PyPI 0.1.0 has only `train` and `dev` (docs/inference.md, Environments for serving), and Gemma 4 support is on `main` only.
2. **Request body.** Same System One shape as Jev: `state`, `questions` map with `{"type":"noul"|"choice"|"score","instructions":..,"criteria":..}`. `model` is accepted (the docs example sends `"model":"hobson-latest"`); the README example omits it, so it is optional (inference from the README curl without it). `state` may be empty "when the question carries the whole task". Option descriptions may be a string, structured data, or `null`. With `--vision`, `images` (base64) may be included. Sources: README and docs/inference.md (Serve).
3. **Free-text instruction.** YES, within the window. The question text is free-form. The 4,096-token window is quoted from the "Gemma 4 models" section of docs/inference.md ("The models are trained and served at a 4,096-token window"), so for the Qwen3.5 v1 checkpoint it is an inference. The authoritative per-checkpoint value is `max_length` in `strands_decider_config.json` (docs/inference.md, Model artifact: "the window (`max_length`)"); README only says the v19 recipe "saves a 4096-token window". The adapter must read `max_length` at startup (or from `/health` if it exposes it; not confirmed) instead of hard-coding 4,096. The gate is unaffected (about 1.3k policy tokens plus a post fits, and `--strict-window` catches overflow). Server behaviour:  "a prompt longer than the checkpoint's window is shortened to fit: the state is cut, and the question keeps its options" and `--strict-window` makes the server return HTTP 422 instead (docs/inference.md, Serve and Gemma 4 models). The 5015-byte policy (about 1.3k tokens, inference) plus a post fits but consumes about a third of the window. WARNING from the v19 model card (the card is for hobson-v19; README says v1 adds "rule-application rows (apply a written policy to a case)", so the caveat may be weaker for v1; unmeasured): "Questions are read less than documents. With the state and options fixed, a changed question often gets the same answer", and "`score` and `noul` transfer poorly to rubrics and yes/no tasks unlike the training mix" (https://huggingface.co/StrandsAgents/strands-decider-2B-hobson-v19, Limitations). So a long policy placed in `instructions` may be largely ignored. Putting the policy in `state` and the post in `state` alongside it is an alternative the docs do not address. Use `--strict-window` in the eval so truncation can never silently drop the policy or post.
4. **Response shape.** README example:
   ```json
   {"model":"strands-decider-2B-qwen3.5-v1-2610","answers":{"is_urgent":{"type":"noul","noul":0.8581}},"usage":{"input_tokens":86,"output_tokens":1},"latency_ms":489.01}
   ```
   choice answers carry `choice`, `probabilities` per option and `confidence` ("the top probability, rescaled so that an even split gives 0 and a certain answer gives 1"). noul "returns the probability of 'true'". All three types "come out of the same masked softmax" over the options, so choice probabilities are normalised over the supplied options, and noul is a two-option softmax (README "Model Architecture"; docs/inference.md "Ask"). Calibration is "one temperature per primitive", fitted on short classification, and confidence bands "are established there only" (model card Limitations).
5. **Batching.** One `state` with many questions per request: "The state is encoded once and its KV cache is broadcast across the question batch" (docs/inference.md, "Asking many questions is nearly free"). `--max-batch N` (default 32) and `--max-batch-tokens N` bound the forward pass. Many posts in one request means many questions about one shared state, not independent states, so the policy cannot be sent once for N separate posts. The server's "behaviour under concurrent requests is not verified" (docs/inference.md, Serve). HARD ADAPTER RULE: serialize requests (concurrency 1). docs/inference.md (MLX section) says "Evaluations run one at a time, because `_fit` keeps a request's option offsets on the engine for `_option_idx` to read; the torch engine has the same race (#9)", so concurrent requests can return wrong answers. Design: one post per request, strictly sequential.
6. **Billing and usage.** No money cost per request (self-hosted). Spend is machine time. `usage.input_tokens` and `usage.output_tokens` are returned (README) and `latency_ms` is returned. Cancellation: NOT FOUND (no cancel endpoint documented; a client disconnect's effect on a running forward pass is not documented). Billing of cancelled requests: not applicable to a local server. Gate reasoning: real cost is zero marginal dollars, so spend is bounded by construction; usage is still reported.
7. **Price.** No per-token price; Apache-2.0 weights (README License). Hardware: Qwen3.5-2B-Base weights download about 4.5 GB at first use (docs/inference.md, Model artifact). Reference latency: median 115 ms per JevBench question on an RTX 3090; Apple M4 Pro with `--device mlx`: 113 ms at 222 input tokens, 486 ms at 1,118, 1,764 ms at 4,094 (docs/inference.md, Serving on a Mac with MLX; those are v19 figures, v1 is stated to have "same architecture and size as v19" in the README performance table).
8. **Rate limits.** None (local). Concurrency behaviour "is not verified" (docs/inference.md, Serve) and a known race (#9, `_fit` option offsets) exists, so concurrency must be 1 (docs/inference.md, MLX section).
9. **Data retention / training.** Data stays on the local machine; the server has no telemetry documented in the pages read (NOT FOUND either way; I did not read the weights' dependency telemetry). The Hugging Face download at first use contacts huggingface.co but sends no post text.
10. **Identity.** YES. Response `model` is the checkpoint name (for example `strands-decider-2B-qwen3.5-v1-2610`). `GET /health` also reports the checkpoint path and base model. Releases are tagged `YYMMDD` on the Hub, and a same-month re-release updates `main`; pin with `hf download StrandsAgents/strands-decider-2B-qwen3.5-v1-2610 --revision YYMMDD --local-dir v1` then `strands-decider serve v1` (docs/inference.md, Model artifact). Without pinning, `main` can change under you.

## Cross-provider notes for Part B

- Output mapping: the policy says "Output 1 ... 0 ... single digit". All three providers use the same System One shape. A two-option `choice` is the only form with probabilities normalised over the answer set, so use `choice` with `criteria` keys `"1"` and `"0"` (or `toxic` / `clean`) rather than `noul`. Which key naming scores better is unmeasured.
- Jev and Clef return `probabilities` and `confidence`; compare on `probabilities[toxic-key]`.
- Idempotency: none of the three documents an idempotency key.
- Compatibility: Cloudflare states Clef "follows the same System One API" as Jev (https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/), and Strands' docs say "Compatibility with the Jev API itself is not verified" (docs/inference.md, Serve). A single request builder is plausible but each provider's response must be tested separately.

- Cancellation and billing of aborted/timed-out calls: NOT FOUND for Jev and Cloudflare.
- Cloudflare Unified Billing behaviour at zero credit balance: NOT FOUND. AI Gateway spend limits are Beta.
- Strands v1 `max_length` (window) is read from the checkpoint config, not confirmed at 4,096 for Qwen3.5 v1.
- Maximum questions per request for Jev: NOT FOUND.
